- **Implementation decisions:**
  - Pure JVM Reducer: `TransferReducer.reduce(state, event): ReducerResult` has zero side effects, returning the next immutable state and a list of pure effect descriptions.
  - Asynchronous Race Convergence: On receiver item verification, `StreamEof` (with byte count & hash), `TransportPayloadSuccess` (bulk stream finish), and `ItemEndReceived` (sender expected hash) can arrive in any order. The reducer records arrival flags and only initiates destination commit when all three are satisfied.
  - Retaining Verified Items: Per `STATE_AND_DATA_MODEL.md`, `ItemPhase.Verified` is absorbing. If cancellation occurs after commit of item $N$, that item remains verified, while subsequent unverified items are cancelled and partial files deleted, producing a valid partial batch outcome.
  - Terminal State Absorption: All terminal states (`Completed`, `Cancelled`, `Failed`, `Interrupted`, `DeliveryUnconfirmed`) are absorbing. Late callbacks, byte progress, or duplicate controls return the identical state and empty effects.
  - Receipt Ambiguity: If a timeout occurs on the sender while awaiting receipt (`SessionPhase.AwaitingReceipt`), the session transitions to `DeliveryUnconfirmed` rather than `Failed`.
