## 1. Summary of Changes

Delivered **Milestone M21**, concluding the final step (Step 6) of the Glide Cross-Platform Path ([`CROSS_PLATFORM_PATH.md`](../../future/CROSS_PLATFORM_PATH.md)), establishing the zero-cloud remote/internet transfer architecture, NAT traversal pipeline, blind relay anti-abuse policies, metered cellular data protections, and remote threat model:

1. **Architectural Decision Record Authored & Accepted ([`docs/adr/ADR-0022-remote-internet-transfer.md`](../../adr/ADR-0022-remote-internet-transfer.md)):**
   - Evaluated central cloud storage relays (rejected: violates zero-cloud invariant, introduces surveillance and storage costs), centralized user account directories (rejected: violates zero-account/zero-tracking invariant), and zero-knowledge E2EE peer-to-peer NAT traversal with ephemeral blind relays (adopted).
   - Defined out-of-band remote pairing URIs (`glide://remote/v1#...`) encoding ephemeral rendezvous IDs, X25519 public keys, signaling endpoints, and blind tokens.
   - Enforced zero-knowledge signaling broker isolation (stateless forwarding; payloads E2EE encrypted).
   - Defined direct P2P NAT traversal via ICE (RFC 8445) and STUN (RFC 8489) UDP hole punching with fallback to blind TURN relays (RFC 8656).
   - Established relay anti-abuse controls: 100 MB per-transfer relay cap (direct P2P transfers are uncapped), IP connection rate limits, and cryptographic blind tokens.
   - Mandated metered cellular data detection and explicit user confirmation dialogs before transferring over mobile networks.
   - Added ADR-0022 to authoritative index in [`docs/adr/README.md`](../../adr/README.md).

2. **Remote Internet Transfer Technical Specification ([`docs/future/REMOTE_INTERNET_TRANSFER_SPECIFICATION.md`](../../future/REMOTE_INTERNET_TRANSFER_SPECIFICATION.md)):**
   - Authoritative 8-section specification covering Executive Summary, Remote Signaling Architecture, NAT Traversal Pipeline, End-to-End Cryptographic Wire Framing, Blind Relay Anti-Abuse Controls, Consent & Metered Data Protection, Remote Threat Model additions (Threats R01 to R08), and 5-phase implementation roadmap (Phases R1–R5).

3. **Threat Model Expansion ([`GLIDE_THREAT_MODEL.md`](../../security/GLIDE_THREAT_MODEL.md)):**
   - Formally documented Threat IDs R01 (Unauthorized Remote Ingress / Spam), R02 (Signaling Relay Snooping / Traffic Analysis), R03 (Blind Relay Bandwidth Abuse / DoS), R04 (MITM on Remote Wire), R05 (Metered Data Bill Shock), R06 (Stale Invitation Replay), R07 (Remote Executable Ingress), and R08 (Cloud Dependency Creep) with mitigations and test criteria.

4. **Automated Specification Auditor ([`tools/verify-remote-transfer-spec.ps1`](../../../tools/verify-remote-transfer-spec.ps1)):**
