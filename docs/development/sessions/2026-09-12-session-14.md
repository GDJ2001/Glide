# Development Session Report: 2026-09-12-session-14

## 1. Objectives and Task Scope
- **Task:** `GLIDE-014` — Implement Nearby control and bulk mapping.
- **Milestone:** M3 — First real device transfer.
- **Scope:**
  - Implement Nearby Connections `BYTES` control messaging and `STREAM` bulk payloads behind the pure `:transfer-core` `TransferTransport` port.
  - Enforce strict 16 KiB (`ProtocolLimits.MAX_CONTROL_PAYLOAD_BYTES`) wire ceiling on control messages; reject oversized and empty control payloads.
  - Implement opaque `BulkRef` mapping binding decimal signed Nearby payload IDs to domain bulk references.
  - Implement `prepareStream` to acquire the opaque payload ID reference ahead of `ITEM_START` announcement.
  - Enforce `READY` handshake: suspend payload streaming until `markItemReady` (or `ITEM_READY`) is acknowledged by receiver, with a 30s monotonic timeout.
  - Implement bounded pending map (capacity $\le 2$) holding unmapped `STREAM` payloads unopened with a 30s deadline to resolve payload-before-metadata arrival races.
  - Enforce one-stream-maximum constraint across both sender and receiver, rejecting concurrent streams.
  - Enforce duplicate payload rejection, dropping redundant callbacks without double admission.
  - Normalize callback order and completion flags: `BulkProgress` marks completion strictly upon `PayloadTransferUpdate.Status.SUCCESS` and stream EOF.
  - Implement robust cancellation and disconnect teardown: immediately cancel Nearby payloads and close stream descriptors.
  - Build comprehensive test suite covering the 5 required scenarios: payload-before-metadata, duplicates, unmapped stream, cancel, and exact length.

## 4. Threat Model & Security Review
- **T01 / T02 (Eavesdropping & MITM):** Control messages and streams are transmitted strictly over authenticated, encrypted Nearby point-to-point links; payloads received from unauthenticated/disconnected peers are dropped immediately without processing.
- **T05 (Malformed / huge metadata):** Control payloads strictly capped at 16 KiB (`ProtocolLimits.MAX_CONTROL_PAYLOAD_BYTES`); oversized envelopes are rejected before network submission.
- **T07 (Disk exhaustion / oversized stream):** Bounded stream streaming enforces exact byte boundaries and immediate cancellation on error.
- **T08 (Spam / DoS):** Enforced one-stream-maximum constraint; bounded pending unmapped stream map (capacity $\le 2$) with 30s monotonic auto-cancellation prevents memory/resource exhaustion attacks.
- **T10 (Logs leakage):** Zero payload data or private identifiers emitted to system logs.
- **T17 (Consent race / process death / false success):** READY handshake guarantees receiver acceptance before stream transmission; completion flags are normalized so that neither sender nor receiver marks completion before physical EOF and SDK `SUCCESS`.
