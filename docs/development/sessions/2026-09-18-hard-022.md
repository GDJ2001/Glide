## Scope completed in source

HARD-022 now has a role-aware Android durable resume authority rather than the earlier
offset-only prototype.

### Durable v5 journal

`ResumableSessionEntity` is keyed by original transfer session + item and records the local
journal role.

Receiver authority stores:

- authenticated peer fingerprint;
- total size, fixed chunk size and original chunk-root hash;
- only the contiguous verified chunk count/byte offset;
- locally computed SHA-256 digests for exactly that retained prefix;
- a private staging directory;
- creation/update timestamps and 24-hour expiry.

Sender authority stores:

- authenticated peer fingerprint;
- persisted source handle and deterministic source identity;
- total size, fixed chunk size and original chunk-root hash;
- whole-file SHA-256 from bounded preflight;
- creation/update timestamps and 24-hour expiry.

Version-4 resume rows are deliberately dropped by `MIGRATION_4_5`. They do not contain the
peer/source/role/prefix authority required to be safely upgraded.

### Contiguous receiver recovery

A receiver chunk can advance the durable journal only when it is exactly the next chunk.
The chunk is hashed locally and written in private staging. Room compare-and-advance updates the
count, offset and verified-prefix digest list together. Restart reconciliation re-hashes every
retained chunk and rewinds/deletes the suffix from the first missing/corrupt chunk.

Final promotion requires:

1. every chunk in the contiguous prefix;
2. a recomputed complete chunk-root equal to the original offered root;
3. a recomputed whole-file SHA-256 equal to the authenticated final digest;
4. verified promotion before the resume journal is removed.

### Source/permission/peer authority

`ResumeSourceVerifier` performs a bounded fresh re-read of the current Android source and derives:

- deterministic source identity;
- current total size;
- per-chunk SHA-256 values and complete chunk root;
- whole-file SHA-256.

Changed bytes, changed size, early EOF/growth, permission loss or source unavailability do not
reuse the old sender journal as authority.

Peer revocation purges that peer's retained resume state. Local identity rotation purges all
retained resume authority. Explicit user cancel purges the original transfer's retained state;
service/process interruption deliberately does not use that explicit-cancel path.

### Resume offer handoff

The canonical offer model now reserves the exact initial authority needed by later native resume:
when `resume-v1` is negotiated, a resumable item carries the inseparable pair
`rootHash` + `chunkSize`. Kotlin and .NET codecs reject malformed pairs and Android/.NET
runtime paths reject those fields when `resume-v1` was not negotiated.

Android sender preflight and receiver journal hooks are wired through the existing coordinator and
DI graph, but `enableTrueResumeCapability` remains **false** in production. This is intentional:
HARD-023 must provide equivalent desktop durability and HARD-024 owns real interrupted
cross-platform resume validation before the capability can be release-enabled.
