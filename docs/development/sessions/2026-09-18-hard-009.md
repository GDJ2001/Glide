## Scope

HARD-009 hardens the Android foreground-service/session boundary so UI recreation and backgrounding observe one service-owned session, terminal actions target the exact session, orderly cancellation cannot tear the service down before storage/transport cleanup, and startup recovery never converts abandoned work into false success.

## Production changes

### 1. Terminal cleanup barrier in `TransferCoordinator`

Added an explicit terminal cleanup barrier:

- terminal transition installs the barrier **before** publishing terminal state;
- `DeletePartialDestination` executes under the configured I/O dispatcher before cleanup completion;
- `CancelBulkStream` is awaited instead of fire-and-forget;
- `CloseTransportChannel` gets its bounded terminal-control flush opportunity and disconnect is attempted before cleanup completion;
- prepared source streams are closed before the barrier completes;
- `awaitTerminalCleanup()`, `cancelAndAwaitCleanup()`, and `interruptAndAwaitCleanup()` expose the lifecycle contract to the service/runtime.

This fixes the prior race where `TransferRuntime` could observe `Cancelled`/`Failed`, invoke terminal teardown, cancel the service scope, and thereby abort cleanup jobs that had only just been launched.

### 2. Runtime teardown waits for cleanup

`TransferRuntime` now:

- waits for `TransferCoordinator.awaitTerminalCleanup()` before invoking the terminal service callback;
- converts service ownership loss into `Interrupted` and runs best-effort coordinator cleanup;
- returns the cleanup `Job` from `detachServiceScope()` so the service can keep its scope alive until cleanup finishes;
- no longer clears an active coordinator immediately on explicit stop; it requests protocol cancellation and lets the terminal lifecycle own teardown;
- distinguishes an already-terminal coordinator from an active cancellation request.

UI-visible state still becomes interrupted promptly when service ownership is lost; durable cleanup proceeds under the captured service scope.

### 3. Foreground service lifecycle

`TransferService` now:

- treats duplicate start intents with the same operation key as idempotent no-ops;
- retains the duplicate-start key through terminal teardown, clearing it only when the service is actually destroyed;
- lets `ACTION_STOP` request active cancellation and waits for the normal terminal callback instead of immediately stopping foreground ownership;
- on `onDestroy`, defers `serviceScope.cancel()` until the runtime cleanup job finishes when such a job exists;
- preserves existing `START_NOT_STICKY` behavior, so process death never fabricates a reconnect.

Start keys cover generic session start, Nearby sender, Nearby receiver, LAN sender and LAN receiver without logging invitation secrets.

### 4. Startup reconciliation

`GlideApplication` now passes `transferRuntime.activeSessionId.value` into `ProcessDeathReconciler.reconcile()`.

This uses the reconciler's existing active-owner protection when an in-process session already exists, while abandoned sessions remain eligible for interruption/partial cleanup.

## Test changes and evidence mapping

### New/strengthened current-task tests

`TransferRuntimeTest`:
- `detachServiceScope_interruptsNonTerminalOwnership_andPreservesRetryState` now waits for the cleanup job and proves the coordinator reaches a terminal state and transport disconnect occurs;
- `stopActiveSession_requestsCancellationAndWaitsForTerminalCleanup` proves explicit service stop reaches `Cancelled`, clears active-session state through terminal observation, disconnects transport and invokes the terminal callback exactly once.

`StaleCancelActionTest`:
- duplicate service-start keys are accepted once and rejected on exact replay until reset;
- stale accept/reject notification actions cannot affect the current offer;
- existing stale/missing/exact cancel coverage remains.

`TransferCoordinatorTest`:
- `cancelAndAwaitCleanup_returnsOnlyAfterTransportDisconnect` proves the cleanup barrier does not return before disconnect;
- terminal integration tests now call `awaitTerminalCleanup()` before asserting history, committed files or discarded staging, eliminating terminal-state/durable-effect races.

### Existing qualifying evidence retained

`TransferServicePolicyTest` and `PermissionLifecycleMatrixTest` cover:
- API 31+ background-start restriction;
- API 34 connected-device prerequisites;
- API 37 LAN local-network permission;
- notification-permission denial not being treated as FGS authorization denial.

`LifecycleMatrixTest` covers:
- activity/ViewModel recreation rebinding to one process runtime without creating a second transfer owner;
- lock-before-consent never auto-accepting;
- network disruption mapping to `Interrupted`;
- process/task death recovery preserving verified files and interrupting unfinished work.

`ProcessDeathReconcilerTest` covers:
- abandoned pre-commit work -> partial purge + session/item `Interrupted`;
- verified commit boundaries recovered idempotently;
- missing durable files never presented as valid;
- `activeSession_isPreservedAndNotInterrupted` when the active session ID is supplied;
- completed items in a partially interrupted batch remain completed.

These are behavioral tests; they are not source-pattern-only acceptance evidence.
