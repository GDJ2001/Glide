# HARD-015 — Desktop consent, history, settings and UI state

## Status

**REVIEW_REQUIRED** on `hardening/continue-2026-09-18`.

## Implementation

- WPF incoming offers now wait on an explicit Accept/Reject modal after authenticated bootstrap and before bytes.
- The obsolete SAS modal/interaction contract was removed from the production desktop interface.
- `DesktopStateStore` persists only non-secret receive settings and verified history, using bounded history and atomic file replacement.
- WPF loads history/settings at startup, exposes receive folder and listener-port settings, and uses the configured receive destination.
- UI callbacks are marshalled through the WPF dispatcher.
- Receive invitations stop advertising when consumed, refresh after a session, and rotate before their 120-second expiry while idle.
- The WPF listener serializes inbound sessions instead of spawning unbounded transfer tasks.
- Interactive CLI receive also asks for explicit offer authorization.
