## Fail-closed unattended startup

`glide daemon` no longer starts an unattended receive surface by itself.

The command now requires:

`glide daemon --policy <policy.json> [--port <port>]`

Missing, unreadable or invalid policy returns a non-zero startup result before the listener is created.

The policy requires:

- an absolute receive destination;
- an absolute sensitive enrollment-file path;
- 1–32 exact allowed remote IP addresses;
- maximum item bytes;
- maximum batch bytes;
- maximum item count;
- invitation lifetime between 60 and 3600 seconds;
- an optional bounded device display name.

Persistent cryptographic peer identity is intentionally not invented in HARD-016. Until HARD-018–021, daemon authorization is bound to BOTH an exact configured network peer address and possession of a fresh one-use QR/invitation bearer.

## One-use enrollment lifecycle

For each enrollment window the daemon:

1. generates a fresh invitation bound to the actual listener port and current TLS SPKI;
2. creates one `LanInvitationAuthority`;
3. writes the invitation URI to the configured enrollment file instead of journald/stdout;
4. restricts the file to user read/write on Unix;
5. accepts only a TCP peer whose remote IP is explicitly allowed;
6. requires the normal invitation bootstrap/token/hash checks;
7. removes the bearer file when the invitation is consumed;
8. removes/rotates it when its monotonic TTL expires;
9. removes it again during orderly shutdown.

Enrollment-file deletion is fail-loud rather than silently leaving a stale bearer behind.

Wrong-token/replay protection remains the shared HARD-012 `LanInvitationAuthority` boundary.

## Explicit unattended offer policy

The daemon interaction no longer auto-authorizes arbitrary authenticated offers.

`DaemonReceivePolicy.AuthorizesOffer` requires:

- at least one item;
- item count within policy;
- every item within the configured per-item ceiling;
- aggregate bytes within the configured batch ceiling;
- aggregate item bytes exactly matching the declared offer total.

The shared desktop receiver also received `DesktopReceiveLimits`. These limits are advertised in HELLO_ACK **and independently enforced server-side before consent/storage**. A malicious peer cannot bypass the daemon policy merely by ignoring advertised limits.

Interactive `glide receive` retains the HARD-015 explicit y/yes consent path and is separate from unattended daemon policy.

## Destination/storage policy

The daemon creates the shared `QuarantineStagingStore` with the configured destination. Existing HARD-014 reservation/quarantine/digest/commit behavior remains the storage authority.

An accepted offer can still be rejected before payload authorization if the shared store cannot reserve sufficient local capacity. This preserves the existing `INSUFFICIENT_STORAGE` / destination-unavailable semantics rather than allowing partial public writes.

## Hostile connection resilience

TLS/connection setup failures are isolated to the current enrollment window. A malformed/hostile connection is logged as rejected and does not terminate the long-running daemon.

Remote-address authorization occurs before application bootstrap processing. Unauthorized addresses are disconnected without consuming the invitation authority.

## Cancellation and shutdown

Ctrl+C and POSIX SIGTERM feed one cancellation token.

The internal `RunDaemonWithPolicyAsync` loop is cancellation-driven so tests can exercise shutdown without signaling the test runner itself. Cancellation propagates through accept and active transfer operations.

The packaged systemd user unit now includes:

- required `--policy %h/.config/glide/daemon-policy.json`;
- `KillSignal=SIGTERM`;
- `KillMode=mixed`;
- `TimeoutStopSec=15s`;
- `SendSIGKILL=yes`;
- `UMask=0077`;
- `NoNewPrivileges=true`;
- `PrivateTmp=true`;
- `ProtectSystem=strict`;
- `ProtectHome=read-only`;
- explicit `ReadWritePaths` for the packaged Downloads/XDG configuration layout.

A custom destination requires an equally narrow corresponding `ReadWritePaths` adjustment; weakening the sandbox is not implied.
