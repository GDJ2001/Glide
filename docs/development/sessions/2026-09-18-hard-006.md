## Result

HARD-006 replaces optional/fake production discovery/advertising providers with a process-owned production Nearby controller and point-of-use permission flow.

## Production wiring delivered

- `ProductionDiscoveryController` owns real Nearby discovery and advertising over `NearbyTransferTransport`.
- Permission and hardware readiness are revalidated immediately before radio start.
- Production `DiscoveryViewModel` and `ReceiveReadinessViewModel` observe `TransferRuntime`; no-argument instances fail closed.
- `TransferRuntime` exposes typed start/stop discovery, receive availability and permission-denied commands/state.
- Navigation3 requests runtime Nearby permissions at point of use for Send and Receive.
- Permission denial blocks discovery/advertising and does not start radio work.
- Bluetooth/Wi-Fi/location/Play Services readiness maps to blocked production UI state.
- Discovery preserves peer ordering while marking loss unavailable.
- Advertising surfaces the exact Nearby authentication digits from the SDK connection event.
- Debug/release Nearby service-ID selection derives from the application debuggable flag instead of relying on generated BuildConfig.

## Behavioral evidence

`ProductionDiscoveryControllerTest` proves:

1. denied permission results in zero discovery/advertising starts;
2. granted permission starts real controller discovery;
3. peer appearance/loss updates stable runtime state;
4. hardware blocks prevent radio start;
5. advertising surfaces the exact authentication digits and peer identity;
6. discovery timeout stops radio work;
7. runtime-backed Discovery/Receive ViewModels observe one production authority.

Existing discovery/receive acceptance tests were migrated to explicit test harnesses so fake/optional providers cannot enter production wiring.
