## Failure-gate proof

The immediately preceding CI run **35285947126** reached source and failed the Android job at the behavioral LAN gate because `StorageStreamingBenchmarkTest.discardStaging_cleansUpDiskImmediately` exceeded its 50 ms benchmark budget on the shared runner. Ordinary tests and later steps were blocked/skipped by that failure.

Investigation showed the staged file had been deleted correctly; the measured 92 ms included `Dispatchers.IO` scheduler contention. The benchmark was corrected to inject an unconfined test dispatcher while retaining both the actual file-removal assertion and the 50 ms operation budget. The authoritative run then passed `checkLanGate`.

This sequence proves a real failing ordinary test blocks the CI job; no production storage behavior or acceptance threshold was weakened.

## HARD-003 expected-red integration

The workflow separately runs the intentional HARD-003 regressions. Those steps succeed only when:

1. the dedicated regression sources compile,
2. the isolated regression command returns non-zero because actual test cases fail, and
3. a recorded failed-test result exists.

They therefore preserve red-before-fix evidence without making the ordinary baseline permanently red.
