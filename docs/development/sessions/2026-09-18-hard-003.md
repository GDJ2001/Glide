## Regression surfaces

### Desktop / daemon / native protocol

`windows/Glide.Tests/Hard003DesktopRegressionTests.cs` covers:

1. **Headless daemon bootstrap must fail closed without invitation authority.**
   - Current behavior accepts an arbitrary bootstrap when `invitation == null`.
   - Fix owner: HARD-016, with native interoperability proof in HARD-017.
2. **Direct unpaired sender/receiver SAS must match.**
   - Latest evidence observed sender/receiver codes `783602` and `123607` for the same connection.
   - Fix owners: HARD-012 and HARD-013.
3. **Offer pagination must advertise the real page count.**
   - 33 offered files require two pages; current production sender advertised `pageCount=1` instead of `2`.
   - Fix owner: HARD-013.
4. **Control sequence must remain strictly monotonic across items.**
   - Current evidence observed first `ITEM_END seq=6`, followed by second `ITEM_START seq=5`.
   - Fix owner: HARD-013.
5. **Pre-transfer hashing must remain bounded-memory.**
   - A 32 MiB file allocated approximately `33,832,376` bytes before the offer page, above the 12 MiB regression budget.
   - Fix owner: HARD-014.

### Browser gateway security

`windows/Glide.Tests/Hard003WebGatewayRegressionTests.cs` covers:

1. Onboarding URL requires encrypted transport (`https`, not current `http`).
2. Redeemed onboarding credential must not remain a reusable bearer credential.
3. Upload requires an accepted proposal/upload identifier.
4. Upload without declared digest must be rejected even after proposal acceptance.
5. Proposal upload identifier must be consumed exactly once.

Current gateway behavior fails all five expectations. Fix owners: HARD-025 through HARD-030.

`transport-lan/src/test/kotlin/dev/glide/transport/lan/web/Hard003WebGatewaySecurityRegressionTest.kt` mirrors the browser security contract on the Kotlin side so later implementations cannot silently diverge.

### Android production wiring

`app/src/test/kotlin/dev/glide/app/hardening/Hard003ProductionWiringRegressionTest.kt` covers:

1. A production `DiscoveryViewModel` with no real discovery/runtime dependency must fail closed rather than claim that discovery is running.
2. A production receive-readiness ViewModel with no real advertising dependency must fail closed rather than claim that advertising is active.
3. Receive QR state must not become `Ready` solely from caller-supplied/example endpoint and fingerprint data when no live listener/runtime authority exists.

`app/src/androidTest/kotlin/dev/glide/app/hardening/Hard003ReceiveQrRuntimeRegressionTest.kt` additionally preserves the live-device receive-QR boundary for later instrumentation/device execution.

Fix owners: HARD-005 through HARD-010, especially HARD-006 for production discovery wiring and HARD-008 for live LAN listener/QR authority.

## Regression isolation

The intentional red tests are quarantined rather than disabled:

- .NET: xUnit trait `HARD=003-red`.
- Android/Kotlin: Gradle property `hard003Regression=true` selects `Hard003*`; ordinary test tasks exclude them.
- CI includes explicit expected-red evidence steps that fail if the regression command unexpectedly becomes green before the corresponding production fixes, and also fail if the command exits non-zero without an actual failed-test result.

This preserves a green ordinary baseline for HARD-004 while retaining deterministic red-before-fix evidence for later TDD remediation.

## Non-goals / remaining work

HARD-003 did **not** repair daemon authorization, SAS synchronization, native sequencing/pagination, streaming hashing, Android production composition, or browser security. Those production changes remain owned by HARD-005–030 as mapped above. Hardware-only and cross-platform physical evidence also remains outside HARD-003.
