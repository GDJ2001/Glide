# HARD-014 — Bounded desktop hashing and storage flow

## Status

**REVIEW_REQUIRED** on `hardening/continue-2026-09-18`.

## Implementation

- Sender no longer computes SHA-256 by loading the full file into memory.
- SHA-256 is updated incrementally in the same bounded streaming pass that writes DATA records.
- Sender records source length/mtime and rejects a changed source instead of certifying stale metadata.
- Receiver enforces declared size during DATA, verifies STREAM_END byte count, hashes incrementally, and verifies ITEM_END SHA-256.
- Failed/quarantined items are purged; verified items commit through the shared `QuarantineStagingStore`.
- Relative paths are validated through the shared storage sanitizer.
- Terminal batch success is based only on verified items.
