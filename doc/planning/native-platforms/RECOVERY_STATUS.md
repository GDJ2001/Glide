## Exact next implementation work

1. **Apple identity and invitation:** the identity factory and ready-listener invitation publisher compile on macOS/Xcode. Pass that identity into the application listener and connect the existing one-use authority to the production session engine. Publish an invitation only after the listener reports a bound port, using reachable interface addresses and the SPKI of its presented certificate. `IosTransferViewModel.generateLocalInvitation` and `MacTransferViewModel.generateLocalInvitation` intentionally publish no placeholder code today.
2. **Apple protocol engine:** replace the deliberate failure boundary in `GlideTransferEngine` with full bootstrap, HELLO/ACK, capability negotiation, paged OFFER/decision, ITEM_START/READY, bounded DATA, ITEM_END with independently verified digest and length, ITEM_RESULT, BATCH_END/RESULT, cancellation, timeouts, and one-active-batch ownership. Do not re-enable the old direct-stream code. Use `QuarantineStagingStore.finalizeAndCommit(expectedSha256Hex:expectedLengthBytes:destinationDirectory:rawFilename:)` only after authenticated ITEM_END.
3. **Apple app integration:** connect incoming listener dispatch, user offer consent, sender-hosted recipient confirmation, trusted identity enrollment/revocation, verified history, and security-scoped file access. The Share Extension target built at `a7106fb`; subsequent cancellation, serial file-provider import (including Photos), off-main queue ingestion, and retained document leases are source-implemented through `e60afdf`. Retrieve its pending target-host build and fix any diagnostics, then validate App Group handoff on a signed device. See [iOS share handoff](IOS_SHARE_HANDOFF.md) for ownership rules and deferred validation cases. Register `group.dev.glide.shared` in Apple Developer provisioning before a signed device build. Build app, extension, and package on a Mac before claiming any Apple implementation gate.
4. **Linux qualification:** Linux–Windows backend transfer, framing, authentication, consent, cancellation, and storage safety are verified on Ubuntu 24.04 WSL 2 (75 PASS, 0 FAIL, 1 BLOCKED for WSL 2 virtual NAT mDNS; report `doc/testing/LINUX_WINDOWS_BACKEND_VALIDATION_REPORT.md`). Next is running the Avalonia desktop flows in a desktop VM on Ubuntu 24.04 and Fedora Workstation 44 for frontend UI appearance, accessibility, window behavior, and camera QR scanning.
5. **Release engineering:** finish target-host packaging for Windows, Android, and Apple with clean-commit manifests; then assemble exact artifact hashes from those manifests. The retired `tools/package-distributions.ps1` cannot create release evidence. Run Phase 2 only after these implementation slices and R10 pass.
6. **Storage recovery:** review the bounded private quarantine and public temporary cleanup and destination-local commit behavior on target hosts. During Phase 2, execute the new folder-preflight and cleanup regression cases, then cover cross-volume destination, disk-full copy, symlinked parent, and crash between copy and rename on Windows and Linux.

## Release rule

Report **implementation complete** only after R10. Report **program validated** only after all Phase 2 checks have evidence against the final commit and exact artifacts. Missing Mac/Linux hosts, devices, or participants keep the corresponding gates open.
