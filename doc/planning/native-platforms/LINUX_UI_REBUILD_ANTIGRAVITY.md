# Glide Linux UI rebuild — Antigravity execution plan

**Planning baseline:** 2026-10-04. The observed application is Glide 1.0.0 installed in the Windows-hosted VirtualBox VM `ubuntu-26.04.1` (Ubuntu 26.04.1 LTS, amd64, 1280×800 display), built from `7a8afa1233ba4a0329c5c7d63110f4afb1373837`. Linux UI source is unchanged between that commit and planning HEAD `a9f37ef8c7dec8efed8e92a9f95d5b58a42dd31f`. [Baseline screenshot](../../evidence/linux-ui/ubuntu-26.04.1-baseline.png). The screenshot is local development evidence, not a usability or transfer validation result.

**Goal:** Make the Linux app as clear and finished as the established Windows and Android clients while fitting Ubuntu/GNOME desktop conventions. Keep Avalonia 12/.NET 10, Glide branding, the current native transfer protocol, authenticated invitations, explicit recipient/offer consent, and one active batch. Do not add a browser transfer UI, unsupported pause/resume, or a new backend protocol.

## 1. Findings that drive the work

| ID | Priority | Evidence | Consequence and required response |
|---|---|---|---|
| LUI-01 | Blocker | VM screenshot: several page headings overlap at the top and Settings covers the content. `MainWindow.axaml` binds each page's `IsVisible` to the string `CurrentTab` with `ConverterParameter` but no `Converter`. | Show exactly one page. Replace string-to-Boolean visibility bindings with a typed page state and a single active `ContentControl` or explicit Boolean page properties. Test the rendered visual tree, not only `CurrentTab`. |
| LUI-02 | High | VM: every navigation button has the same gray appearance. The same converter-less `CurrentTab` binding is used for each button's `Background`. | Add a real selected, hover, pressed, disabled, and focus style. The active destination must be unmistakable by color, shape, and accessible state. |
| LUI-03 | High | VM: the sidebar says `Listening: False` and the status dot is gray. XAML binds the Boolean `IsListening` directly to `Fill` with a color as `ConverterParameter`, again without a converter. | Say “Receiving is off” or “Ready to receive”; use typed status properties/resources. Color must never be the sole signal. Provide a direct action when receiving is off. |
| LUI-04 | High | VM: a light native title bar sits above a hard-coded dark client area. `App.axaml` sets `RequestedThemeVariant="Dark"`; `MainWindow.axaml` hard-codes hex colors. | Follow the Linux system appearance by default, with Light/Dark overrides. Align native decorations where the window manager permits; keep legible contrast if it does not. |
| LUI-05 | High | `MainWindow.axaml` contains all five page trees and four full-window overlays in one 400-plus-line view; `LinuxMainViewModel.cs` combines navigation, discovery, invitations, transfers, history, and settings. | Split the presentation into page views/view models and reusable components. Retain existing runtime services and security behavior. |
| LUI-06 | High | Send source presents a large empty staged-file list, nearby and trusted lists, a raw invitation field, and two separate send buttons simultaneously. The visible VM shell wastes most of the page. | Use one file queue that changes from drop state to list state, followed by a single-choice sending method. Reveal only controls needed for the chosen method. |
| LUI-07 | High | Receive and Pair each expose invitation entry; Send also exposes an invitation field. Copy refers to “listener,” “URI,” endpoints, and identity checks in primary flows. | Give each page one job, use plain instructions, and put endpoints/fingerprints in details. Keep fresh invitation authentication explicit. |
| LUI-08 | High | The four confirmation/QR overlays are `Border` layers with no visible focus-trap/restore or Escape handling in the view. Fixed 440-DIP widths and a bottom transfer overlay risk covering content at minimum size. | Introduce one accessible dialog host with focus containment, restoration, keyboard actions, and a scrollable small-window layout. Keep the active transfer visible without obscuring controls. |
| LUI-09 | Medium | `App.axaml` forces dark; the Send peer row uses a phone emoji; several labels are 10–12 DIP and version text exposes implementation details. | Use a bundled vector icon family, consistent Glide logo, 14-DIP body copy, readable secondary text, and an ordinary About section. |
| LUI-10 | High | `LinuxPresentationTests` checks tab strings and view-model properties, but does not assert page visibility, selected nav styling, focus, or layout. The project explicitly disables Avalonia compiled bindings. | Add render-level UI tests and enable compiled bindings where practical; use a documented exception only for genuinely dynamic bindings. Add a VM screenshot matrix before completion claims. |
| LUI-11 | High | `tools/package-linux-native.sh` declares Ubuntu 24.04's `libicu74`. The supplied Ubuntu 26.04.1 `.deb` was repacked with `libicu78` metadata and has not been rebuilt from the final UI source. | Make native Ubuntu 26 packaging reproducible from a clean commit, then install and smoke-test the resulting `.deb` in this VM. Do not hand-edit a release package's control metadata. |

The root cause in LUI-01/02/03 is supported by [Avalonia binding syntax](https://docs.avaloniaui.net/docs/data-binding/data-binding-syntax): `ConverterParameter` only supplies a value to an actual converter. The visible overlap is direct VM evidence; other page-specific findings above are source observations to verify after LUI-01 is fixed. Avalonia 12 documents [compiled bindings](https://docs.avaloniaui.net/docs/data-binding/compiled-bindings) and [binding diagnostics](https://docs.avaloniaui.net/docs/data-binding/binding-debugging) for catching similar errors.

## 2. Target experience and visual contract

Use the Windows application's navigation and Glide blue/neutral brand language as the cross-platform baseline, adapting controls and window behavior to Ubuntu/GNOME. The UI/UX Pro Max review supports a restrained, functional desktop design, visible keyboard focus, named controls, and low motion. Its marketing-page layout and GSAP suggestions do **not** apply to a native file-sharing application. GNOME recommends progressive disclosure, system-aware light/dark styling, and layouts that work on a 1024×600 display: [principles](https://developer.gnome.org/hig/principles.html), [appearance](https://developer.gnome.org/hig/guidelines/ui-styling.html), [adaptive layout](https://developer.gnome.org/hig/guidelines/scaling.html).

**Shell:** Default to Send. Keep Send, Receive, Activity, Pair devices, and Settings navigation; anchor Settings at the bottom. A compact rail is allowed when narrow but every icon requires a visible tooltip and accessibility name. Show a small “Ready to receive”/“Receiving is off” state near navigation, never a Boolean. Preserve the active transfer across navigation. Use a normal resizable GNOME window and native controls. Initial size around 1040×720; all core actions must remain reachable at the existing 760×520 minimum and on a 1024×600 display. Do not solve overflow with overlapping content or inaccessible horizontal scrolling.

**Tokens:** Put semantic colors, typography, spacing, radii, icon sizes, focus ring, and status styles in shared Avalonia resources. Start from Glide blue `#2457E6` and the Windows semantic roles (`AppBackground`, `Surface`, `SurfaceRaised`, `TextPrimary`, `TextSecondary`, `Border`, `Success`, `Warning`, `Error`, `Focus`); tune contrast separately for Light, Dark, and high contrast. Follow system theme by default; store the Linux-only override separately from transfer settings. Use one bundled vector family and the existing Glide brand asset. Body text should be at least 14 DIP, with readable secondary text. Standard controls should be at least 36–40 DIP high. Use text and icons with status colors.

**Send:** One file-queue card starts as a compact drop target with **Add files** and **Add folder**. On staging, the same card becomes a list with names, sizes, total, remove, clear, and skipped-item explanations; its add controls remain available. Below it, provide three mutually exclusive methods: **Quick share with QR**, **Nearby device**, and **Saved device**. QR immediately opens a scannable one-time code; the sender confirms the recipient before revealing files, and there is no second Send button. Nearby shows discovery states and asks for the selected device's fresh invitation before enabling **Send files**; discovery is availability, not authentication. Saved device shows trusted identity, still requires a fresh invitation, verifies the saved fingerprint, then enables **Send files**. Keep raw addresses behind Details. Preserve staged files after recoverable failure and make Try again start a new authenticated attempt.

**Receive:** Lead with “Ready to receive” or “Receiving is off,” the control to change it, device name, and destination folder. Show QR/link and copy/refresh only when a valid listener and invitation exist. Incoming offer dialog shows peer name, item count, total size, destination, and Accept/Decline. Consent is required even for a trusted peer. Place “Connect to a sender's code” in a focused secondary panel rather than mixing it with the primary receiving control.

**Pair devices:** This page explains how a device becomes saved: verified identity plus an optional trust decision after a real authenticated transfer. Offer **Paste invitation** and **Find nearby** as one-choice connection entry points, with contextual guidance. Provide the local QR only when the relevant listener/selected-file state actually supports it. Never imply that selecting a discovered device has already paired or authenticated it. Return to Send with the selected context intact.

**Activity:** Active batch first with phase, current file, bytes, progress, rate, verification and Cancel. Below it, provide searchable verified history, Sent/Received filters, outcome text, and Open folder. Show current-session failed/cancelled results without adding them to verified history. Clarify missing/moved files. A clear-history action needs a meaningful confirmation or reversible path.

**Settings:** Group Appearance, Receiving, Trusted devices, Advanced connection settings, and About. Device name and destination belong in Receiving. Put port, local addresses, and fingerprints in Advanced or contextual Details. Trusted-device revoke must be explicit. Derive displayed app version from build metadata rather than a hard-coded `.NET 10` label.

**Dialogs and feedback:** Use an actual modal host with initial focus, trapped Tab sequence, Escape/Decline, focus restoration, accessible title/description, and cancellation handling. Pairing/QR dialogs show expiry and regenerate state. Keep errors actionable; technical details are expandable. Show “Complete” only after verified receiver result. Honor reduced motion. Avalonia exposes automation peers to Linux AT-SPI; add names and state and verify with Orca ([Avalonia accessibility](https://docs.avaloniaui.net/docs/app-development/accessibility)).

## 3. Antigravity implementation sequence

Complete all product implementation (A0–A6) before the formal validation phase (V0–V4). Compile and do short developer smoke checks while implementing so a broken page does not compound; those checks do not count as final validation.

| Step | Exact work and likely files | Exit condition |
|---|---|---|
| **A0 — Baseline and binding repair** | Read `AGENTS.md`, `doc/planning/native-platforms/RECOVERY_STATUS.md`, this plan, the baseline screenshot, `MainWindow.axaml`, `LinuxMainViewModel.cs`, and `LinuxPresentationTests.cs`; query Graphify first. Reproduce on the Ubuntu VM. Replace converter-less page/status/nav bindings. Make only the active page part of the displayed content and make selected state real. Add a minimal rendered-view regression test. | Launch shows Send only; changing each destination displays one page and a selected nav item. No overlap at 1280×800. |
| **A1 — Presentation foundation** | Add semantic resources under `desktop/linux/Glide.Linux.UI/Resources/`, vector icons, Light/Dark/System handling, reusable button/card/status/empty/QR/dialog styles. Break `Views/MainWindow.axaml` into a shell and page views. Extract page state from `ViewModels/LinuxMainViewModel.cs` into focused page view models or presenters without duplicating runtime ownership. Enable compiled bindings where typed views allow it. | One visual system, no structural emoji, no hard-coded per-control hex palette, no reflective binding failures in key screens. |
| **A2 — Send and Pair** | Build the transforming file queue and single-choice method controller. Wire picker, drag/drop, clear/remove, folder expansion, QR, nearby, saved identity, invitation validation, retry, and recipient confirmation to the existing runtime. Use explicit enabled/busy/error states. | Every Send/Pair action has a real handler; the route to a transfer is unambiguous and authenticated. |
| **A3 — Receive and Activity** | Build receiving availability, QR/link, consent and destination UX; then global active transfer and history views. Keep cancel and progress across navigation. Surface verification separately from byte progress. | Explicit offer approval, visible active batch, usable completion/Open folder, no false success. |
| **A4 — Settings and accessibility** | Build grouped settings and theme persistence; trusted-device inspection/revocation; modal focus; keyboard shortcuts; automation names/states; high contrast and long-text behavior. Keep settings storage separate from transfer settings. | Keyboard-only core flow and dialog closure work; Linux appearance follows system by default. |
| **A5 — Packaging** | Update `tools/package-linux-native.sh` so the Ubuntu 26 `.deb` is built with correct dependencies on a native Ubuntu 26 environment (including `libicu78`), with source commit and hashes. Keep Ubuntu 24 and RPM packaging intact. Install the package on the VM after implementation. | A fresh `.deb` from the final commit installs, launches, upgrades/removes, and has a verified manifest. |
| **A6 — Implementation freeze** | Reconcile every visible command against production handlers; remove placeholder copy; inspect the diff and update Graphify if architecture changed. Build on Ubuntu and run repository architecture checks. | All pages and states are implemented. Any missing runtime action blocks the freeze. |

Suggested ownership boundaries: a single shell owns navigation and one transfer-banner/dialog host; Send/Receive/Pair/Activity/Settings view models own presentation state; existing `Glide.Desktop`, `Glide.Transport`, and `Glide.Core` remain the security/runtime authority. Do not create a second listener or transfer runtime per page. Preserve the single-instance behavior.
