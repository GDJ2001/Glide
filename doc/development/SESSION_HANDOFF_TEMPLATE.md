# Session handoff template
Copy into docs/development/sessions/YYYY-MM-DD-session-name.md after an actual development session. [Guide](GEMINI_IMPLEMENTATION_GUIDE.md).

- Date / agent / reviewer:
- Branch / starting commit / ending commit or diff identity:
- Task IDs attempted:
- Completed IDs (acceptance evidence linked):
- REVIEW_REQUIRED / remaining IDs:
- Files modified and why:
- Implementation decisions:
- ADR changes / approved deviations:
- Build commands, exit results and artifact paths:
- Tests executed (unit/integration/UI/physical), exact outcomes:
- Device/API/GMS/build identity:
- UI/security/performance checklist evidence:
- Known issues / limitations:
- External blockers and owner:
- Manual validation still required:
- Repository state / unrelated user changes preserved:
- Task ledger percentages and next recommended READY task:
- Relevant docs for next session:

Use “not run” with reason when appropriate. Never include signing secrets, private user files, tokens, raw URIs or peer names. A handoff is evidence, not a substitute for task acceptance.
