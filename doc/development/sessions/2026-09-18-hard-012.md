# HARD-012 — Native LAN profile alignment

## Status

HARD-011 remains REVIEW_REQUIRED because current-head CI is not scheduling. This implementation therefore does not claim completion of the dependency or native interoperability gate.

## Implementation

Desktop LAN Profile 1 was aligned to the Android production contract:

- DNS-SD now uses only `v=1`, `tv=1`, `q=1`, a 128-bit lowercase-hex presence id `p`, bounded device name `dn`, and device type `dt`.
- Discovery no longer advertises certificate fingerprints, pairing tokens, or trust/resume capability claims.
- TLS is TLS 1.3 with ALPN `glide-lan/1`.
- Initial invitation pairing authenticates the receiver by the exact SPKI SHA-256 pin and does not require an unrelated TLS client certificate.
- A new `LanInvitationAuthority` canonicalizes invitations before publication, atomically consumes them, rejects replay, expiry, wrong token/hash, and bounds replay memory.
- Desktop production send no longer has a direct host/port SAS fallback. BOOTSTRAP is mandatory.
