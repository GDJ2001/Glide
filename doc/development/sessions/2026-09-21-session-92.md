## Summary

This session delivers **Step 4 Phase A5** of the Apple platforms development path: the macOS menu-bar companion coordinator, Finder drag-and-drop coordinator, App Sandbox entitlements, and macOS manifest — together with full unit test coverage for both coordinators.

The verify script (`verify-apple-platforms-spec.ps1`) was also hardened to track the new source files, and Check 2 / 5 / 7 / 8 / 9 / 10 were reconciled with the HARD-002 rewritten specification.

## New Source Files

### `apple/GlideCoreKit/Sources/GlideCoreKit/Lifecycle/MacCompanionCoordinator.swift`

Implements the macOS status-bar state machine required by spec § 6.2.

| Symbol | Description |
|--------|-------------|
| `MacCompanionStatus` | `idle \| advertising(port) \| transferring(peerName, progress, bytesTransferred, totalBytes) \| paused \| error(message)` |
| `MacMenuAction` | All menu actions: `openDownloads`, `sendFiles`, `pauseReceiving`, `resumeReceiving`, `showHistory`, `toggleLaunchAtLogin`, `selectPeer(spkiFingerprint)`, `quit` |
| `MacMenuItem` | Rendered menu item model (`title`, `subtitle`, `isEnabled`, `isSeparator`, `action`) |
| `IMacNetworkListenerProvider` | Protocol abstraction over `NWListener` lifecycle (production / mock) |
| `MacCompanionCoordinator` | Thread-safe (`NSLock`) coordinator. `defaultPort = 42424`. Methods: `startListener()`, `stopListener()`, `setTransferring(…)`, `completeTransfer()`, `setError(…)`, `setOpenAtLogin(_:)`, `setDownloadsDirectoryUrl(_:)`, `statusItemTitle`, `statusItemToolTip`, `generateMenuItems(discoveredPeers:)` |

### `apple/GlideCoreKit/Sources/GlideCoreKit/UI/MacDropTargetCoordinator.swift`

Implements Finder-drop file collection and batch preparation.

| Symbol | Description |
|--------|-------------|
| `MacTransferRequest` | Value type bundling `peer`, `batch`, `sessionId`, `initiatedAt` |
| `MacDropTargetCoordinator` | Thread-safe coordinator. Static limits: `maxItemSizeBytes = 64 GiB`, `maxBatchSizeBytes = 256 GiB`, `maxItemCount = 10,000`. Methods: `expandAndFilterUrls(_:)`, `collectFiles(at:result:visitedPaths:)`, `shouldIgnoreFilename(_:)`, `validateDrop(fileUrls:)`, `prepareDropBatch(from:)`, `initiateTransfer(batch:)` |

Filters `.DS_Store`, `__MACOSX`, and `._*` metadata files. Detects circular symlinks via canonical path set.

### `apple/GlideCoreKit/Resources/Glide.entitlements`

Apple plist XML granting the five sandbox entitlements required for a macOS companion app:

- `com.apple.security.app-sandbox`
- `com.apple.security.network.client`
- `com.apple.security.network.server`
- `com.apple.security.files.user-selected.read-write`
- `com.apple.security.files.downloads.read-write`

### `apple/GlideCoreKit/Resources/Info.plist`

macOS manifest with:
- `LSUIElement = true` — menu-bar agent (no Dock icon)
- `NSBonjourServices` → `_glide._tcp`
- `NSLocalNetworkUsageDescription`
- `NSCameraUsageDescription`
- `NSPhotoLibraryAddUsageDescription`

## Limitations Acknowledged (per HARD-002 spec)

The coordinator and resource files delivered in this session are **component-level abstractions**, not a certified macOS companion application:
- `DefaultMacNetworkListenerProvider.startListener()` toggles an in-memory Boolean — no real `NWListener`
- No `AppKit`/`NSStatusItem` runtime is wired up
- No Apple ↔ Android/Windows/Linux physical interoperability evidence exists

These limitations are explicitly documented in `APPLE_PLATFORMS_SPECIFICATION.md` § HARD-002 evidence note and Table in § 9.
