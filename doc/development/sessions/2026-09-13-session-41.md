## 1. Objectives and Task Scope
- **Task:** `GLIDE-041` — Implement restrained motion and haptics.
- **Milestone:** M6 — Premium UI (Task 7 of 9 in M6, overall 41 of 68).
- **Priority:** P2.
- **Scope & Acceptance Criteria:**
  - Define centralized motion tokens in `:designsystem` (`GlideMotion`) adhering strictly to `GLIDE_DESIGN_SYSTEM.md`:
    - Control press/selection: 80–120ms state change, small standard spring with no bounce overshoot.
    - Card appearance / peer discovered: 160–220ms fade with $\le 8\text{dp}$ travel.
    - Sheet/dialog appearance: 220–300ms standard Material easing.
    - Navigation: 200–300ms relationship-preserving lateral slide and crossfade.
    - Pairing / connection phase changes: 180ms crossfade.
    - Transfer progress: Interpolate samples 150–250ms, linear within known byte progress; never simulated increments.
    - Completion: Exactly one 240ms check transition, then permanent static state.
    - Failure: Calm 160ms state change, zero frantic shaking or repeated vibrations.
    - Discovery / Receive: Slow 2.4s low-amplitude tonal breathing only while actively searching/advertising; no radar sweep implying measured distance.
  - Implement reduced-motion overrides:
    - Query system animator scale (`Settings.Global.ANIMATOR_DURATION_SCALE` $\le 0.05\text{f}$), transition animation scale, and Android 14+ `AccessibilityManager.isReducedMotionEnabled`.
    - In-app `ReducedMotionPreference` (`SYSTEM`, `ON`, `OFF`) exposed in Settings Appearance section.
    - When active, all transitions and animations collapse to instant (`snap()` / 0 duration) while preserving full state clarity and usability.
  - Lifecycle-aware animations:
    - Zero offscreen infinite animations: decorative discovery and receive readiness breathing animations halt when app is backgrounded (lifecycle not `RESUMED`), under reduced motion, or when inactive, immediately returning static 1.0f alpha.
  - Restrained, accessible haptics:
    - `GlideHaptics` interface: light selection, connection confirmation, success, and error.
    - Device-found haptic is strictly off by default to avoid continuous buzzing in dense RF environments.
    - Vibration is never used alone to convey status.
    - Respects system touch feedback settings (`Settings.System.HAPTIC_FEEDBACK_ENABLED`).
  - Permissions and lint:
    - Added `<uses-permission android:name="android.permission.VIBRATE" />` to satisfy Android Lint `MissingPermission`.
  - Testing & Physical Verification:
    - 100% passing tests in `MotionTokensTest.kt` (4/4), `ReducedMotionResolverTest.kt` (4/4), `GlideHapticsTest.kt` (4/4), and `MotionAcceptanceTest.kt` (4/4).
    - Clean `verify-local.ps1` with 0 errors and 0 lint warnings.

## 2. Implementation Summary

### Design System Motion & Haptic Tokens (`:designsystem`)
- `designsystem/src/main/kotlin/dev/glide/designsystem/Motion.kt`:
  - Defined timing constants: `ControlPressDurationMs` (100ms), `CardAppearanceDurationMs` (200ms), `SheetDialogDurationMs` (250ms), `NavigationDurationMs` (250ms), `PairingPhaseCrossfadeMs` (180ms), `TransferProgressDurationMs` (200ms), `CompletionCheckDurationMs` (240ms), `FailureDurationMs` (160ms), `DiscoveryBreathingDurationMs` (2400ms).
  - Defined standard Material easing curves: `EnterEasing` (Decelerate), `ExitEasing` (Accelerate), `StandardEasing` (Standard / Peak).
  - Defined `SpringSpec` with critical damping ratio ($1.0\text{f}$) ensuring zero overshoot.
  - Defined `LocalReducedMotion` composition local and helper methods `resolveSpec` and `tweenOrSnap` to transparently collapse animations to `snap()` when reduced motion is enabled.
- `designsystem/src/main/kotlin/dev/glide/designsystem/Haptics.kt`:
  - Defined `GlideHaptics` interface: `performSelection()`, `performConfirmation()`, `performSuccess()`, `performError()`, `performDeviceFound()`.

  - Added `reducedMotion: Boolean` and `haptics: GlideHaptics` parameters to `GlideTheme`.
