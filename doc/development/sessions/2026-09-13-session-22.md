# Development Session Report: 2026-09-13-session-22

## 1. Objectives and Task Scope
- **Task:** `GLIDE-022` — Handle unknown/transient sources with bounded staging.
- **Milestone:** M4 — Foreground MVP.
- **Scope & Acceptance Criteria:**
  - Stage unknown-length sources (cloud providers like Google Drive, Dropbox, or Nextcloud returning null or negative sizes) and non-persistable transient grants (Android Share Sheet ingress) into local app-private cache with a bounded 64 KiB buffer before an offer is made.
  - Acceptance criterion: Cloud/provider unknown sizes must **never** become false zero-byte protocol offers; memory usage must remain strictly $O(1)$ (< 256 KiB) with **zero whole-file RAM loading**.
  - Enforce free disk safety reserve margin (minimum 256 MiB) and protocol item ceiling (`MAX_ITEM_BYTES` = 64 GiB).
  - Synchronously delete partial `.part` files immediately on cancellation, timeout, or failure.
  - Required automated tests: Unknown size, provider hang, cancellation, disk exhaustion, transient grant lifetime.
  - Live emulator validation with visual evidence on `Pixel_10` AVD (Android 17).

## 2. Execution & Evidence Summary
- **Bounded Staging Engine (`BoundedSourceStager.kt`):**
  - Implemented `BoundedSourceStager` in `:data` module.
  - Fixed 64 KiB buffer (`BUFFER_SIZE = 64 * 1024`) ensuring streaming I/O with zero whole-file RAM buffering.
  - Enforced disk safety margin (`diskReserveBytes = 256 * 1024 * 1024L`) checked both prior to staging and in-flight after every buffer write.
  - Provider hang detection using coroutine `withTimeout(readTimeoutMs)` wrapping `runInterruptible(ioDispatcher) { input.read(buffer) }` for real thread interruption.
  - Atomic rename from `.part` to `.staged` on completion; synchronous file deletion of `.part` files in `catch (e: Throwable)` block on any error or cancellation.
  - Clean lifecycle management: `cleanup(handle)`, `cleanupAll()`, and orphan cleanup `cleanupOrphans(maxAgeMs)` for orphaned staging files.
- **AndroidSourceAccess Integration (`AndroidSourceAccess.kt`):**
  - Integrated `val stager: BoundedSourceStager? = null` into `AndroidSourceAccess`.
  - In `validateSource`: unknown or negative size query results (`sizeBytes == null || sizeBytes < 0L`) trigger `stager.stageSource(...)` with optional `onStagingProgress` callback, measuring exact byte counts and returning validated `SourceMetadata`. Direct direct offers never receive a 0-byte size for cloud/unknown files.
  - In `openSource`: if source is staged, opens directly from `stager.openStagedSource(handle)` (app-private file input stream), bypassing external provider grants.
  - Added `cleanupStaged(handle)` and `cleanupAllStaged()`.
- **Selection UI Integration (`SelectionUiState.kt` & `SelectionScreen.kt`):**
  - Added `SelectionUiState.StagingSource(displayName, bytesStaged, isCloudProvider)` to `SelectionUiState`.
  - In `SelectionScreen.kt`, instantiated `BoundedSourceStager` with app cache directory `staging_sources/` and passed to `AndroidSourceAccess`.
  - Added live progress reporting during file preparation in `onUrisSelected`.
  - Rendered `StagingSource` state card with circular progress indicator, live human-readable staged byte count, cloud download disclaimer ("Downloading from cloud provider before transfer..."), and accessible Cancel button with immediate `.part` deletion and cache purge.
  - Added automatic staging cleanup on `onBack()` and "Clear all" clicks.
