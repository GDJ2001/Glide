# HARD-013 — Strict desktop protocol/session state

## Status

**REVIEW_REQUIRED** on `hardening/continue-2026-09-18`.

## Implementation

The shared desktop engine now enforces protocol-v1 session semantics rather than relying on ad-hoc per-item sequence values:

- Independent outbound/inbound control sequences start at 1 and increase exactly by one.
- Ordered TLS/TCP input treats a gap, stale sequence, wrong session, or unexpected control type as a protocol violation.
- Control reads have a 30-second deadline; transfer-record reads have a 60-second deadline.
- Offers are paged at the Android/shared maximum of 32 items, with a conservative payload ceiling.
- Receiver consumes all declared pages in exact index order and verifies item count plus byte totals.
- BOOTSTRAP precedes HELLO and the session id must remain identical.
- Batch/item/bulk-reference values are correlated exactly at every state transition.
- Sender validates ITEM_RESULT size/hash and BATCH_RESULT totals.
- Any failed item prevents the local result from being reported as a fully successful batch.
