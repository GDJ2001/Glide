# Development Session Report: 2026-09-13-session-20

## 1. Objectives and Task Scope
- **Task:** `GLIDE-020` — Implement sequential batch scheduling and partial outcomes.
- **Milestone:** M4 — Foreground MVP.
- **Scope & Acceptance Criteria:**
  - Strict sequential batch scheduling across pure STREAM transport with zero concurrent transfers.
  - Advance to the next item only after preceding item is verified and committed via `ITEM_RESULT(status = "verified")`.
  - Partial failure handling: when a middle item fails (e.g. `INTEGRITY_MISMATCH`), retain previously committed files on disk; discard the failing item's staging; mark future queued items as `ItemPhase.NotAttempted`.
  - Cancellation handling: when user cancels before next item, preserve earlier committed files on disk; mark active/future items as `Cancelled` / `NotAttempted`.
  - Lost final receipt handling: when all items are verified and receiver emits `BATCH_RESULT`, but connection drops before sender receives it, sender transitions to `SessionPhase.DeliveryUnconfirmed` with failure `TransferFailure.DeliveryUnconfirmed()`, while receiver records `Completed` with all files retained.
  - Required automated tests: empty/mixed files, fail middle item, cancel before next item, lost final receipt.

## 2. Execution & Evidence Summary
- **Domain & Event Upgrades:**
  - `ReducerEvent.kt`:
    - Enhanced `ItemResultReceived` with `val bulkRef: BulkRef? = null` parameter, enabling dynamic bulk payload reference resolution when advancing to the subsequent item in the batch.
- **Deterministic Reducer Enhancements (`TransferReducer.kt`):**
  - Updated `ItemResultReceived` handler to consume `event.bulkRef` when advancing to the next item, assigning the correct bulk reference to `ActiveItemState`.
  - Added robust detection of lost final receipts in `handleTransportFailure`:
    - When `state.role == DeviceRole.Sender` and `state.phase == SessionPhase.AwaitingReceipt`, connection drops or transport disconnects transition the session to `SessionPhase.DeliveryUnconfirmed` with `TransferFailure.DeliveryUnconfirmed()`.
    - Session and item outcomes are persisted honestly (`DeliveryUnconfirmed` for session, preserving `Verified` for all verified items).
- **Coordinator Upgrades (`TransferCoordinator.kt`):**
  - **Per-Item Staging Directory & Isolation:**
    - Replaced single staging handle with synchronized map `stagingHandles = Collections.synchronizedMap(mutableMapOf<ItemId, StagingHandle>())`.
    - Tracked list of committed files `committedFiles: List<CommittedFileHandle>`.
    - Staging handles are created upon `PrepareDestination(itemId)`, tracked by `itemId`, committed into `committedFiles` upon `CommitDestination(itemId)`, and safely deleted on `DeletePartialDestination(itemId)`.
  - **Sequential Stream Dispatching:**
    - When sender receives `ITEM_RESULT(status = "verified")`, sender opens source stream for the next item, calls `transport.prepareStream { stream }` to obtain the next `BulkRef`, and dispatches `ReducerEvent.ItemResultReceived` with the generated `bulkRef`.
    - Emits `ITEM_START` with the matching `bulkRef` and launches `transport.sendStream` sequentially, ensuring zero concurrent streams.
  - **Payload Race Protection:**
    - Synchronized retrieval and brief polling of `stagingHandles[curItem.item.id]` in `observeIncomingStreams` ensures payload streams arriving ahead of or concurrently with control metadata never suffer `NullPointerException` or dropped streams.
- **Automated Verification Suite (`TransferCoordinatorTest.kt`):**
  - Implemented 4 new comprehensive end-to-end batch test cases with simulated network transports and storage adapters:
    1. `sequentialBatch_happyPath_mixedFiles_transfersAllPreservingOrderAndOutcomes`: Verifies 3 mixed files (small text, binary payload, zero-byte file) transfer sequentially in exact index order, both sides reach `SessionPhase.Completed`, and receiver commits all 3 files retaining byte-for-byte fidelity.
    2. `sequentialBatch_failMiddleItem_retainsEarlierCommittedFilesAndMarksLaterNotAttempted`: Injects SHA-256 corruption into item 2; verifies item 1 is committed and retained on disk, item 2 fails verification and staging is deleted, item 3 is never attempted (`NotAttempted`), and session outcomes reflect `Failed`.
    3. `sequentialBatch_cancelBeforeNextItem_preservesEarlierCommittedFiles`: Cancels transfer immediately after item 1 commits; verifies file 1 is retained on disk, item 2 is marked `Cancelled`, item 3 is marked `NotAttempted`, and both coordinators enter `SessionPhase.Cancelled`.
    4. `sequentialBatch_lostFinalReceipt_terminatesInDeliveryUnconfirmedWithVerifiedFilesRetained`: Drops receiver's `BATCH_RESULT` and drops connection; verifies sender enters `SessionPhase.DeliveryUnconfirmed` with all items `Verified`, while receiver enters `SessionPhase.Completed` with all files retained on disk.
