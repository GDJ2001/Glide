## 4. Threat Model & Security Review
- **T01 / T02 (Eavesdropping & MITM):** All communication is mediated through verified point-to-point Nearby Connections transport; unauthenticated payloads are dropped.
- **T03 (Spoofed Identity):** Sender metadata and transfer batch items are cryptographically and structurally validated; unauthenticated streams are not committed.
- **T04 (Offer Tampering):** Offer begin/pages/end assembled and validated through `OfferAssembler`; receiver consent required before stream transmission.
- **T05 (Malformed / Huge Control Messages):** Protocol envelope and body decoded strictly via `ProtocolCodec`; malformed wire codes rejected.
- **T06 (Path Traversal):** File paths never trusted from peer; receiver writes strictly to isolated staging files via `ReceiveStore` (`noBackupFilesDir/receiving/<itemId>.part`).
- **T07 (Disk Exhaustion):** `ReceiveStore.hasAvailableSpace` validates required bytes plus safety margin prior to accepting offer.
- **T10 (Log Leakage):** No raw payload bytes or sensitive file contents logged.
- **T17 (Consent Race / False Success):** Stream transfer only starts after receiver consent; receiver only commits after SHA-256 digest match; sender only marks complete upon verified `ItemResultBody`.
