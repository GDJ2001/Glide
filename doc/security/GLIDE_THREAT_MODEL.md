## Assets, actors and boundaries
Protect file bytes, source grants, received files, consent, peer verification, history metadata, signing material and user privacy. Attackers include a nearby stranger, malicious connected peer, local app sending intents, malicious document provider, network observer and compromised dependency. OS/root compromise and a malicious recipient after consent are outside the confidentiality guarantee; residual risks remain explicit.

Boundaries: untrusted radio advertisement → SDK authenticated channel → bounded protocol parser → consented domain operation → private storage commit → explicit external file grant. Each boundary validates independently. No account/server exists. Hashing verifies content identity, not human identity or malware safety.

Likelihood/impact are qualitative planning judgments before controls; tests must confirm mitigation, not treat a table as proof.

## Identity and cryptography decision
V1 uses Nearby's authenticated encryption and human token comparison on every connection. No custom handshake, short-code hash or long-term peer trust is added. Android Keystore is appropriate for nonextractable persistent keys if a later reviewed identity protocol needs them; it is not evidence that two phones belong to the same person. Future trust must bind user-verified public keys, support revoke/key rotation and avoid accepting restored trust without key possession. See [ADR-0011](../adr/ADR-0011-trusted-identity.md).

## Privacy requirements
No account, contact access, cloud upload, advertisements, location history, own analytics or crash SDK. Default device name “Glide device”; user may choose a name after explanation that nearby users can see it while visible. History is local, bounded and clearable. Received files have separate explicit deletion. No filenames/peer names in lockscreen public notifications.

Nearby's SDK does collect diagnostic metrics and device information under Google Usage & diagnostics settings; do not market Glide as “zero data collection” without qualification. Glide cannot impose a retention period on Google. No custom diagnostic upload endpoint is planned. Optional user-exported support report contains app/OS version, coarse error code and timing only, user-previewed and manually shared; no automatic upload or file/peer identifiers.

Primary security sources: [Android Keystore](https://developer.android.com/privacy-and-security/keystore), [backup behavior](https://developer.android.com/identity/data/autobackup), [Nearby diagnostics](https://developers.google.com/nearby/connections/overview). SDK-specific privacy review is repeated before release.
