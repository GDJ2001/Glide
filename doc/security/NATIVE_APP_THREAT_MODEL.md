# Native Glide application threat model

Updated 2026-10-12. Scope: local-network file sharing and pair-only enrollment between Android, Windows, Linux, iOS/iPadOS, and macOS. Browser file transfer is retired. The status column describes source implementation and automated verification; physical Mac hardware validation remains separately tracked until executed on a macOS host.

| Threat / boundary | Required control | Production source | Status | Phase 2 evidence required |
|---|---|---|---|---|
| Discovery impersonation | Treat mDNS (`_glide._tcp`) and display names as availability candidates only; never advertise PINs, tokens, trust status, or certificate fingerprints in DNS-SD; bind sessions to live TLS 1.3 server certificate SPKI and cryptographic proofs | `MdnsDiscoveryService`, `LanTxtCodec`, `BonjourService`, `DesktopPairingCoordinator`, `Profile2PairingEngine`, `DesktopTransferEngine`; Android `transport-lan`; Apple `GlideTransferEngine` / `Profile2PairingEngine` | Multi-NIC IPv4 mDNS discovery, canonical Apple TXT (`v=1,tv=1,q=1,p,dn,dt` + optional `pair=1,tr=1`), and SPKI-bound session transcripts implemented and verified in C#, Kotlin, and Swift | Cross-platform wrong-PIN, wrong-endpoint, replay fixtures and physical wrong-device attempt |
| Offline PIN guessing / MITM on desktop pairing | Use pinned BoringSSL SPAKE2 (`3fed4f207543470b3d639db6ed40737e30308b51`) over TLS 1.3 (`GLD2` / `PAIR_ONLY`), 120-second one-use 6-digit code, max 3 failed attempts per window, directional HKDF key-confirmation MACs and mutual ECDSA P-256 identity signatures bound to live TLS SPKI, explicit approval on both devices, and zeroing of secret buffers | `GlideSpake2`, `Profile2PairingEngine`, `PairReadyWindowAuthority`, `DesktopPairingCoordinator`, `CGlideSpake2` | Implemented and tested across Windows, Linux, and macOS (`GlideCoreKit`); wrong-PIN attempt ceiling and transcript tampering fail closed | Live Windows↔Windows, Windows↔Linux, and Linux↔Linux 6-digit pairing runs |
| Pair-only vs. transfer confusion or unapproved file delivery on `PAIR_ONLY` | Strictly separate `PAIR_ONLY` (`glide://pair/v2#...`, `purpose=pair-only`) from `glide://pair/v1#...` transfer invitations; reject any `HELLO`, `OFFER`, `DATA`, or transfer record on `PAIR_ONLY`; require explicit recipient consent for every incoming file offer, even from paired peers | `LanSessionPreambleInspector`, `DesktopProfile2Router`, `Profile2PairingEngine`, `DesktopTransferEngine`, `LanTransferTransport`, `GlideTransferEngine` | Implemented and verified across Desktop, Android, and Apple; rogue `OFFER_BEGIN` on `PAIR_ONLY` fails closed with `PROTOCOL_ORDER` | Reject and trusted-peer interactive offer tests on all clients |
| Wrong recipient for sender-hosted QR | Confirm recipient identity before sending selected files | `DesktopTransferEngine.SendHostedAsync`, Windows/Linux recipient prompt | Linux and Windows prompts wired and tested | QR role in both directions, cancel and wrong-name cases |
| Oversized or malformed records | Bound control frames to 16 KiB and bulk chunks to 64 KiB, reject unexpected controls, unknown preambles, and unknown Profile 2 purposes | `PrefixedStream`, `LanSessionPreambleInspector`, `Profile2WireCodec`, `LanRecordChannel`, `DesktopTransferEngine`; Android protocol codec; Apple `LanRecordChannel` | .NET, Android, and Apple enforce 16 KiB control ceiling and fail closed on unknown versions/purposes | Shared malformed and boundary fixtures in Kotlin/C#/Swift |
| Quarantine bypass or corrupt file | Private staging; independently hash actual bytes; compare declared length and ITEM_END digest; commit only after verification | .NET `QuarantineStagingStore`/`DesktopTransferEngine`/`DesktopBatchPreparer`; Android `QuarantineStagingStore`; Apple `QuarantineStagingStore` | Desktop, Android, and Apple stage into `.part` quarantine files, verify streaming SHA-256 against `ITEM_END`, and atomically rename only on match | Corrupt digest, truncation, symlink, collision, disk-full, and restart cases |
| Persistent identity misuse or silent key substitution on trusted reconnect | Enroll peer public key only after mutual cryptographic proof (`PAIR_CONFIRM`) and both users' explicit approval; on `TRUSTED_SEND`, require mutual `identity-v1` signatures over `GLIDE-TRUSTED-SESSION-V1` bound to current TLS certificate SPKI before any file offer; allow TLS certificate renewal only when persistent identity proof matches; fail closed with `Identity changed — pair again` on key change or revocation | `DesktopPersistentTrustManager`, `DesktopTrustedSessionAuthenticator`, `DesktopTransferEngine.SendTrustedAsync` / `ReceiveTrustedAsync`; Android `PersistentTrustManager` / `LanTransferTransport`; Apple `PersistentTrustStore` / `GlideTransferEngine` | Implemented and verified across Desktop, Android, and Apple; rotated TLS cert succeeds when identity matches, rotated identity key or revoked peer fails closed | Enrollment, cert rotation, identity rotation, and revocation tests |
| Concurrent process or batch conflict | One active batch or pairing operation and one per-user listener owner; return `This device is busy — try again` (`BUSY`) on concurrent pairing/transfer attempts | `DesktopTransferRuntime`, `DesktopPairingCoordinator`, `DesktopListenerSupervisor`, `DesktopListenerOwnership`, `TlsSocketListener`, `LinuxSingleInstance` | Single active session ownership enforced across pairing and transfer engines | Duplicate launch, stalled handshake, and concurrent pairing/transfer cases |
| Secret leakage | Never transmit or log 6-digit PINs, raw invitation tokens, full URIs, or private keys; zero PAKE secret buffers after use; restrict desktop and mobile trust/identity stores | `LanInvitation.ToString`, `LanPairV2Invitation.ToString`, `PairReadyWindowAuthority`, `GlideSpake2`, `DaemonInvitationFile`, platform trust stores | Redacted `ToString()`, zeroed PAKE/PIN buffers, and restricted store permissions verified | Log/notification scan and store permission checks |
| Stale or substituted artifact | Build every package from one clean commit; record toolchain and fresh hash; sign outside untrusted PR jobs | `tools/package-*`, `apple/scripts/package-*`, CI workflows | Version preserved at `1.0.0` across all packages | Manifest hash/provenance, install/upgrade/uninstall on target OS |

Residual blockers: physical Mac hardware validation (reported separately until run on a macOS/Xcode host) and physical iOS device execution.
